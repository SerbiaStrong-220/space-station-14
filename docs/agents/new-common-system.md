# Создание обычной системы

Подходит, когда фича собирается из вызовов существующих систем, простой логики и компонентов с данными. Если нужна новая переиспользуемая основа для других систем, читай [new-fundament-architecture.md](new-fundament-architecture.md).

## Порядок
1. **Найди готовое.** Поищи по ключевым словам задачи в `Content.Shared`, `Content.Server` и папках `SS220`. Если система уже решает задачу, используй её и не пиши дубль.
2. **Выбери образец из списка ниже.** В репозитории много устаревших практик. Не копируй код только потому, что он лежит рядом: сверяйся с [csharp-style.md](csharp-style.md) и [ecs-performance.md](ecs-performance.md). Если подходящего образца в списке нет, ориентируйся на соседние системы с современным стилем (`Entity<T>`, `ref`-события).
3. **Пиши:** компонент с данными и система с логикой. Общую часть размещай в `Content.Shared`, серверную и клиентскую вынеси в свои проекты. Обычной системе обычно хватает компонента, системы и событий. Остальные типы (обёртки, ключи, интерфейсы, базовые классы) должны пройти проверку «Минимум типов» из [csharp-style.md](csharp-style.md).
4. **Нужна новая основа для других систем?** Остановись и переходи к базисному файлу.
5. **Перед сдачей пересчитай новые типы.** Для каждого, кроме компонента, системы и событий, ты должен назвать, кто его использует и что без него усложнится. Не можешь — удали тип и используй уже доступные типы или приватный метод.

## Тесты
Для обычной системы тесты по умолчанию не пиши. Если они кажутся нужными, вероятно, логика переусложнена или не использованы готовые системы. Вместо тестов ставь `DebugTools.Assert` (см. «Поддерживаемость кода» в [csharp-style.md](csharp-style.md)). Если всё равно уверен, что тест необходим, спроси разработчика.

## Современные системы-образцы
Список пополняется по мере появления новых паттернов.

### `EntityEffectSystem` (уже существует, используй, а не пиши заново)
Когда: нужно накладывать временные эффекты (урон, замедление и похожее), особенно если на одну сущность может действовать несколько модификаторов или у эффекта есть длительность.
Паттерн: эффект — отдельная сущность, она помещается в контейнер владельца. События, поднятые на владельце, ретранслируются на сущности-эффекты. Это решает конфликт нескольких источников одного и того же изменения на одном компоненте.
Готово из коробки: таймер действия, его обновление и продление.
Найди класс по имени и повтори его паттерн для своего эффекта.
